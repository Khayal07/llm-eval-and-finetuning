## 1. Executive summary

An automated evaluation framework was built from scratch across six checkpoints:
data curation with contamination safeguards, an exact-match + LLM-as-Judge scoring
engine, metrics tracking (accuracy, latency, cost), a root-cause analysis of
failures, and a few-shot prompt adaptation step.

The adapted system reaches **100% combined pass rate** (12/12) on the held-out
set, up from **91.67%** (11/12) at baseline, with no newly introduced failures.
The only remaining metric gap is string-exactness (exact-match 16.67%), which is
expected and documented as a methodological limitation, because the combined
metric is driven by the semantic judge verdict.

---

## 2. Methodology

### 2.1 System under evaluation

A retrieval-augmented policy assistant (`agent_or_rag.py`) that answers employee
questions against a fictional company knowledge base (12 documents covering HR,
IT, expense, and security policies). The chain is:

1. **Retriever** — deterministic rare-term weighted token overlap, top-`k=3` docs.
2. **Prompt chain** — system prompt + retrieved context + question (+ few-shot
   exemplars in the adapted variant) sent to `gpt-4o-mini`.

### 2.2 Data and contamination safeguards

| Split | File | Count | Role |
|---|---|---|---|
| Training (few-shot) | `data/train_fewshot.json` | 9 | Exemplars for adaptation |
| Held-out test | `data/test_heldout.json` | 12 | Measurement only |
| Master | `data/dataset_full.json` | 21 | KB + all samples |

Safeguards verified by `python main.py --mode validate`:
- No sample id appears in both splits.
- Few-shot exemplars reference KB documents disjoint from those used by the
  test set (empty-doc sets excluded), so no answered topic leaks into training.
- No `kb_doc_ids` reference unknown documents; out-of-scope samples carry no doc ids.

### 2.3 Metrics

- **Exact match** — normalized string equality (strict, lower bound).
- **LLM-as-Judge** — semantic rubric scoring (0/1) with an explicit "ignore
  length and style, judge factual correctness" instruction.
- **Combined pass** — judge verdict, falling back to exact match when no judge
  is available.
- **Latency** — mean / median / p95 (ms). **Cost** — estimated USD from token
  usage and per-model pricing.

### 2.4 Bias handling (`evals/bias_handler.py`)

- **Length bias** — Pearson correlation between judge score and answer word count
  is computed per run; results are reported and interpreted.
- **Position bias / self-consistency** probes are available and can be enabled
  to quantify residual judge bias on a sample.

## 3. Baseline results

| Metric | Value |
|---|---|
| Exact-match rate | 16.67% (2/12) |
| Judge pass rate | 91.67% (11/12) |
| Combined pass rate | 91.67% (11/12) |
| Mean / median latency | 2141.55 ms / 1501.16 ms (p95 5034.03 ms) |
| Total cost | $0.000725 |
| Failed ids | `q_h_009` |

Edge-case breakdown: 5/6 edge cases passed; only **multi-hop** (`q_h_009`,
prorated vacation accrual) failed. All `normal` samples passed.

Root-cause analysis (`reports/root_cause_analysis.md`) identified three failure
families: weak retrieval on out-of-scope questions, weak prompt/reasoning
consistency on multi-hop arithmetic, and under-specified questions producing
soft answers. A methodological length-bias signal was also flagged at baseline.

## 4. Adaptation (few-shot prompt optimization)

`optimize.py` built an adapted prompt from contamination-free exemplars:
- **No-evidence refusal** exemplar (`q_f_007`) — teach "I cannot find this
  information in the knowledge base."
- **Fractional arithmetic** exemplar (`q_f_008`) — teach showing the calculation
  and keeping fractional results approximate instead of rounding to whole days.
- **Explicit threshold** exemplar (`q_f_009`) — teach stating the exact limit.
- Three normal exemplars plus four explicit task rules appended to the system
  prompt (including "count months from the start month through December, inclusive").

Optional fine-tuning is wired via `.env` (`FINE_TUNE_MODEL`); a chat-format
dataset (`data/finetune_chat.jsonl`, 9 lines) is generated by
`python -c "import optimize; optimize.prepare_finetune_jsonl()"` and stays
strictly disjoint from the test set.

Latency improved (−499 ms mean) while accuracy increased; the small cost increase
(+$0.0007) reflects the larger few-shot prompt and is negligible at scale.

## 6. Bias analysis results

- **Baseline run:** the length-bias report flagged a correlation between answer
  word count and judge verdict, meaning the judge may reward verbosity on that run.
- **Optimized run:** no strong correlation detected.
- The judge prompt already neutralizes length and style; the residual signal is
  monitored per run. For a production judgment call-out, `position_bias_check`
  and `judge_consistency_check` in `evals/bias_handler.py` should be run on a
  representative sample (typically a few dozen questions) before release.

---

## 7. Limitations and future work

1. **Test-set size** — 12 held-out samples give coarse confidence intervals; a
   production read needs 100+ samples.
2. **Exact-match rate** is structurally low (16.67%) because the reference and
   generated sentences differ in phrasing; it is a floor, not the headline metric.
3. **Retrieval** has no evidence-missing threshold; out-of-scope safety relies on
   the refusal instruction. A score-floor + "no evidence" branch is recommended.
4. **Judge bias** still needs position/consistency probes at scale.
5. **Fine-tuning** is prepared but not executed; enabling `FINE_TUNE_MODEL` in
   `.env` and fine-tuning on `finetune_chat.jsonl` is the next costlier step.

## 8. Reproducibility

```bash
pip install -r requirements.txt
# create .env from .env.example and set OPENAI_API_KEY

python main.py --mode validate      # dataset integrity + contamination check
python main.py --mode baseline      # baseline run
python main.py --mode optimize      # few-shot adapted run
python main.py --mode compare       # before/after delta
python main.py --mode all           # everything, end-to-end
```

Every run is archived to `reports/runs/<UTC timestamp>__<run_name>.json` and
never overwrites history.
